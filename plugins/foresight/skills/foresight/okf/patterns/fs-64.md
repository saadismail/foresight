# FS-64 · Destructive or prod-wide write started without an explicit go-ahead for that scope

An agent treats a feasibility question, a clean dry run, one subagent's widened success, or a broad earlier approval as permission for a production write at a larger scope; read-only subagents run the --apply recipe from muscle memory; sibling fan-out agents keep applying while a policy question raised by one of them is pending. The write lands before the user has confirmed its scope.

**Triggers**
- the user asked 'can you' / 'is it feasible' rather than 'do it'
- a dry run just succeeded and the next command is --apply across many locations/days
- a subagent reports out-of-scope findings or hits a policy gate during a fan-out
- dispatching identify-only agents whose normal recipe includes a write flag
- spawning write-capable parallel workers from a broad queue

**Guards**
- Name the exact scope (count of locations/days/rows) and wait for an explicit go-ahead before any --apply beyond the agreed batch
- Ban the write flag in read-only agent prompts and require the agent to echo each command before running it against prod
- When one agent hits a policy-defining gate, pause every sibling until it is resolved; confirm widened scope with the user before applying it to the rest of the batch
- Make write queues stoppable per item
