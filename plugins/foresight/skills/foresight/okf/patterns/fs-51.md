# FS-51 · Code handles one of several representations of the same fact

The same real-world fact is stored or transmitted several ways: a bank match as an FK or a batch M2M, account_type as a slug or a title-cased label, names with case/slug variants, location scope as a query param or a header, a file on the parent M2M or on per-section child fields, an orphan as a null FK or a detached non-null FK, URL scope under several param names. A query, merge key, guard, finder or test is written against the one representation the author saw first and declared exhaustive, so rows in the other representation slip through.

**Triggers**
- a guard, finder or 'is matched/reconciled' check follows one relation path between two models
- a grouping/merge key uses a raw type or name field that other code canonicalizes
- request scope can arrive via query param or header; a guard allow-lists known URL param names
- a cleanup is verified by searching for the exact string or anomaly signature named in the ticket
- a cross-cutting feature (file tracking, audit) wired to the first model found carrying the field
- a stored-file URL field can hold several URI schemes (s3://, gs://, https) and presigning is wired for only one; the field is rendered as an href in more than one component
- an exclude/ignore list names one build-output dir (.next) in a repo that also holds suffixed variants (.next-live, .next-e2e, .next-verify)
- comparing file paths that come from different producers (absolute vs repo-relative, ./ prefixes)

**Guards**
- Grep the schema for every FK/M2M/through relation linking the two models and every model carrying the field type; cover and test each path
- SELECT DISTINCT the stored values of every key component org-wide before writing a merge key, and reuse the canonicalization the bucket router already uses
- Resolve scope through the existing helper that honors every input channel (scope_to_locations / effective_location_ids) and test the header-only entry point
- Verify cleanups with a broader case-insensitive/pattern search and check the sibling signature (null FK vs detached FK) before declaring done
- Enumerate every link builder that targets a guarded route and test each param variant
- Contract-test that every URL field in API responses starts with https:// for each configured storage backend, and grep every component that renders the field
- Exclude by glob (.next*), then du -sh the staged context and compare it with the source size before shipping
- Normalize both sides to resolved repo-relative paths before comparing, and test absolute, ./-prefixed and relative inputs
