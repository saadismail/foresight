# FS-13 · Styling correct only in the context that was eyeballed

Layout and style are checked at one viewport, one theme, with short seed strings and few rows, inside the page's own DOM root. Other contexts break them: long labels and many rows overflow fixed caps, ultrawide screens stretch, dark mode flips a background token but not its foreground, portaled drawers escape page-scoped selectors, cascade order or specificity overrides variants, z-index collides with the existing scale, popovers overflow without collision logic. In React Native the same happens across locales (taller Arabic text pushes a footer off a non-scrolling screen), narrow devices (an unwrapped row of links overflows its hit areas off-screen), reused shared containers (double borders) and single- vs multiline field modes.

**Triggers**
- fixed px/fr column caps, fixed-size tiles, per-row heights, or height = container / rowCount
- a new class scoped under a page root that may render inside a portal/drawer
- a semantic background token paired with a literal text color, or a new scoped dark-mode override
- a new overlay/popover z-index or anchor without collision handling
- a React Native screen with localized text above action buttons and no ScrollView; a flexDirection: 'row' of tap targets without flexWrap; a shared bordered card/row container reused inside a new form; a new size variant (compact label) in a file with hardcoded offsets; a shared input row with justifyContent: 'center' now hosting a multiline TextInput
- a new modal opened from a page with a fixed/sticky app-shell topbar
- overriding a property set by unlayered legacy CSS with a Tailwind utility or a CSS layer rule; all: unset in unlayered feature CSS; two runtime-injected stylesheets with equal-specificity rules
- a fixed-size native/desktop window or side rail hosting React content verified only in a normal browser viewport
- an optional side panel added to an existing multi-column layout; 12px-or-smaller labels in a subtle/muted ink token
- parallel lanes or worktrees verify UI on freshly seeded per-lane databases (few rows, short names, no history)
- controls and states that render only with data: pinned or saved items, linked rows, long titles, stale or errored third-party integrations, accumulated history

**Guards**
- Screenshot at 1280, 1920 and ultrawide, in light and dark, with 3-5x seed rows and the longest realistic labels
- Pair semantic background tokens with their semantic foreground; grep for text-white/text-black on flipping tokens
- Grep page-root-scoped selectors used inside portaled overlays, and check the app's z-index scale before picking a value
- Unit-test sizing/fit functions at maximum density and against the other constants they interact with
- Screenshot RN screens in the longest-glyph locale (Arabic) and on the narrowest supported device (375pt), with the keyboard open where relevant; wrap localized content in a ScrollView, give rows of tap targets flexWrap, condition container alignment on multiline, and grep the file for hardcoded offsets when a sibling's size changes
- Assert the overlay's z-index exceeds the topbar's and click the modal's own close control in e2e, not only assert visibility
- Check the cascade layer of the rule you override (unlayered CSS beats every cascade layer regardless of specificity), keep feature CSS in a layer, and assert the computed style in e2e
- Render the component at the host window's real size (and with long titles) in the e2e, not in a default viewport
- Screenshot at 1280/1440 with every optional panel open and give the main column a min-width; run axe (serious) on new chrome and use the default ink token below 14px
- Carry the 3-5x-rows / longest-labels guard into every parallel lane brief: seed each lane DB with realistic volume, long labels, pinned/saved items, linked rows and a stale integration before its sweep
- Run the sweep again on the merged tree against production-like data before calling it done; a lane-only pass is not evidence for data-only controls
