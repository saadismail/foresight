# FS-82 · Update endpoint assigns raw request data onto the model instead of going through the serializer

A PATCH/update view or service applies the client dict with setattr (or .update(**data)) while create goes through the DRF serializer. The update path skips type coercion, so wire-format strings reach numeric business-rule comparisons and 500; it skips Serializer.validate() and the ValidationError-to-400 mapping; and it has no writable-field allowlist, so clients can set server-managed fields such as status. Create-path tests pass, and nothing sends PATCH with wire-format strings or forbidden fields.

**Triggers**
- an update/PATCH view or service function takes a raw dict and calls setattr in a loop, queryset.update(**data) or obj.__dict__.update
- business-rule validation lives in Serializer.validate() but the update path never instantiates the serializer with partial=True
- a model with server-managed fields (status, workflow state, computed totals, owner) is exposed through a PATCH endpoint

**Guards**
- Route create and update through the same serializer (partial=True for PATCH) with is_valid(raise_exception=True); grep views and services for setattr over request data
- Write a PATCH test that sends wire-format strings for every numeric/rate field and asserts 400, never 500, on a rule violation
- Write a mass-assignment test per PATCH endpoint that tries every server-managed/read-only field and asserts it is ignored or rejected; declare read_only_fields explicitly
