# FS-55 · Rule keyed on a proxy signal instead of the defining type, status or link

A posting rule, detector, cleanup or guard decides membership from something that usually correlates with the real condition: notes text ('TR FR/TO ...'), the existence of a downstream leg instead of the counterpart FK, an is_matched flag that ORs manual reconciliation with structural pairing, a denormalized date copy instead of the linked rows, a structural flag instead of account_type, every row in a source list without checking department_type, every status instead of the ones the balance sheet reads. Inputs where proxy and truth diverge are silently mis-posted, mis-flagged or deleted.

**Triggers**
- a filter matches free text, notes or naming conventions to identify a class of financial row
- a 'matched/unmatched' or 'safe to delete' decision inferred from a side effect or a conflated boolean
- a business rule says 'only bank-type accounts' / 'only merchandise rows' / 'only REVIEWED' and the function never references that field
- a lock or invariant check reads a denormalized copy on the mutated model
- a build/config guard greps a whole file for a placeholder string instead of reading the one key it validates; a test-data cleanup selects rows by guessing their generated naming pattern
- a cache-hit or fast-path early return tests only the fields one writer fills (transcript present) while the response promises more fields (summary, scores) that another path derives
- classifying tests or endpoints as read-only by HTTP verb or URL while GET handlers may lazily get_or_create shared rows
- a bot loop suppresses events it authored, keyed on the record's reporter or owner

**Guards**
- Filter on the defining field (account_type, department_type, status, the counterpart FK resolved in both directions) and add a fixture with the same text/shape but a different type/status that must be excluded
- Split conflated booleans into separately named signals and have each consumer query the one it means
- Enumerate every status/lifecycle value of the source model and state which ones the rule covers
- Key cleanups and lookups on the canonical identity the sync writer uses ((source_type, source_id)) and resolve the real linked rows, not copies
- Read the exact key path (plutil/jq) in config guards and test with a filled value plus a stale comment; mark test rows at creation and clean up by exact match, not by regex
- Make the early-return condition list every field the response promises, and test with only the webhook-written fields populated
- Back static read-only claims with a row-level DB write audit and flag get_or_create in GET handlers
- Key self-trigger suppression on the actor of the triggering event, not the record's author; test a bot-filed item woken by a human
