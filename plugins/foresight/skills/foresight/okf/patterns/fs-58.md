# FS-58 · One financial total computed by independent code paths that disagree

The same number is computed separately for different consumers: balance sheet vs P&L (only one applies the cross-location suspense adjustment), statement subtotals vs grand total (abs per leaf vs signed sum), the over/short plug vs the ledger writer (different filters for negative rows or disabled entity types), a 'Cash Purchase' from two different models, a reconcile gate vs the apply step's persisted cost. Each path is internally consistent and tested alone; any input the paths treat differently makes the books or screens disagree.

**Triggers**
- a report, plug or summary computes a figure that another report, poster or screen also computes
- adding an adjustment, exclusion or new entity type to one computation of a shared total
- a new cash-movement entity wired into the ledger but not into daily-entry derived totals (over/short, register)
- a delta reported from two totals of the same metric

**Guards**
- Factor the figure into one shared function consumed by every path; derive grand totals from the displayed subtotal lines
- Write a reconciliation test on fixtures containing negative corrections and every contributing entity: sum(posted legs) == stored daily-entry total, subtotals sum to net income, BS and P&L agree
- When adding an entity or adjustment, list every derived total and decide explicitly whether each must include it
- Label every reported total with its source query and assert both bases match before publishing a delta
