# FS-86 · Hand-rolled CSS geometry trusted without a real render

Hand-written CSS layout (pseudo-element connector brackets, absolutely positioned children, repeating print headers, calc() height budgets) rests on layout mechanics the author assumed: the containing block (a missing position: relative), position: fixed in paged media anchoring to the page area inside the CSS page at-rule (page margins) rather than the sheet, a calc() constant that counts only the immediate parent's chrome, and a border shorthand in a :last-child override that clears both lines one pseudo-element draws. jsdom/RTL tests see DOM and text but no geometry, so the full suite is green while the rendered tree is off-centre, headers cover content, a connector vanishes or a scrollbar appears.

**Triggers**
- a hand-rolled CSS tree/bracket/connector built from ::before/::after with absolute positioning, covered only by jsdom/RTL tests
- a print/PDF layout uses position: fixed for a header or footer meant to repeat on every page, or enlarges the CSS page at-rule margin (page margins) to make room for it
- a max-height/height: calc(100vh - Npx) on an inner scroller nested inside several padded or margined wrappers
- a :first-child/:last-child override uses the border shorthand on a pseudo-element that draws two lines (border-top plus border-left)

**Guards**
- For any CSS layout claim (centring, connector lines, no page scroll, repeating header), verify in a real browser or PDF render with a geometric assertion (Playwright boundingBox or screenshot, scrollHeight === clientHeight, pdftotext -bbox on every page of a multi-page render) before calling it done; green jsdom tests are no evidence
- Give the intended container of every absolutely positioned child or pseudo-element position: relative, and assert the rendered offset in the browser check
- Repeat print headers and footers with display: table-header-group / table-footer-group, never position: fixed
- Derive calc() budgets from the sum of every ancestor's padding, margin and border between the viewport edge and the element (or use flex with min-height: 0 instead of a magic constant)
- When one pseudo-element draws two lines, override only the specific side (border-top: 0), never the border shorthand
