# FS-29 · Code assumes the host environment it was written on

Code or config depends on properties of the author's environment: 127.0.0.1 across Docker network namespaces, Docker DNS aliases after going native, localhost resolving to IPv6, PATH in a login shell vs systemd, macOS Python without certifi, GNU vs BSD tools, DB superuser privileges, localhost defaults for absolute URLs, CORS pinned to the default port, unpinned CDN versions, stale topology runbooks. It works locally and fails where it actually runs.

**Triggers**
- a service addressed via 127.0.0.1/localhost/host.docker.internal, or a new base-URL setting with a localhost default
- a daemon shells out to a CLI; a script run on macOS vs Linux; a new tool in a deploy step
- moving a service between Docker and native, or booting on a non-default port
- a CDN script without a pinned version; a runbook/memory describing infra topology
- settings that unconditionally fetch Secrets Manager credentials or define remote DB aliases; a local credential override that can activate in prod; optional binaries/packages (soffice, PyMuPDF) in a fresh sandbox
- a background or non-interactive shell runs python3/node by name; a verification script on a VM calls the VM's own public hostname; a saved SSH/infra connection recipe from an earlier session
- a deploy config reuses an app's default dev ports on a VM that already hosts another app; a relative sqlite path in DATABASE_URL copied into a worktree's .env
- an e2e or preview server falls back to an alternate port because the default is taken
- a stdlib urllib client on a python.org macOS build; writing an absolute machine path into a committed settings file; staging a restore file for a service account under a mode-700 home or tmp dir
- a skill or pipeline helper imports an optional module (fitz/PyMuPDF, numpy, pyzbar) or shells out to a renderer chain (pdftoppm, mutool, magick/convert) or a native lib (zbar), and runs in a fresh per-run sandbox or parallel benchmark worktree (recurs: every parallel sandbox rediscovers the same missing module on its first action even though this trigger was listed)
- building a redirect Location or absolute URL from the request path/host in an app served behind a reverse proxy with a path prefix
- new syntax or stdlib API (backslashes or reused quotes inside f-string expressions, match, newer typing features) in code that also runs on hosts with an older supported interpreter

**Guards**
- Verify reachability from inside the real runtime (curl from the container or systemd unit), not from your shell
- Use 127.0.0.1 vs ::1 consistently between client and server, and derive allowed origins from config rather than the default port
- Check command -v, the platform and DB role privileges before relying on them; use requests/certifi in scripts
- Pin dependency versions and re-check topology (systemctl status / docker ps) once per session before trusting a runbook
- Provide a settings_localtest module for offline tests, gate credential overrides by environment, and pre-flight or fall back for optional dependencies
- Pin absolute interpreter paths in background scripts; verify public endpoints from a different host (clouds don't hairpin NAT); probe saved hosts cheaply before use and update memory in the same change as any infra migration
- Enumerate bound ports on the target (ss -ltnp) and treat ports as deploy inputs; use absolute sqlite paths in DATABASE_URL
- In non-prod allow every port e2e/dev servers may pick in CORS_ORIGIN, or reserve and document one fixed e2e port
- Check a file's git tracked-ness before writing machine-specific values and use the .local override; stage files for a service account with install -o <svc> and check sudo -u <svc> test -r <path> first
- Probe the sandbox once before the first step that needs it (python -c 'import fitz, numpy'; command -v pdftoppm mutool magick; decode a trivial barcode image to prove the zbar dylib loads), record the working choice, and route every later call to it
- Make helpers import optional dependencies inside try/except and fall straight through to the next working renderer or a Pillow/stdlib-only path, and bake native libs (poppler, zbar) into the sandbox image instead of installing them mid-task
- Build public URLs from a configured public base URL (or trusted forwarded headers) and curl the public host to assert the Location header before go-live
- Set the linter/compiler target to the minimum supported runtime (ruff target-version, tsconfig target) and compile or run the tests under that floor interpreter in CI
