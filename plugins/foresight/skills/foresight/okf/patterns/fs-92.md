# FS-92 · Integrity or result gate fails open on missing evidence or trips on non-canonical bytes

A guard or aggregator compares evidence it assumes is present and canonical. A truthy check lets a missing or blank recorded hash through. An aggregator that globs per-shard junit files reports a pass with a smaller denominator when a shard died before writing. A byte-hash guard over a zip that embeds mtimes rejects identical content, and a new optional field serialized unconditionally changes the hash of every old object. Happy-path tests, with inputs present and freshly built, never reach these edges.

**Triggers**
- a guard shaped `if recorded and recorded != actual: raise`, or any integrity check whose recorded value can be absent
- a report or aggregation step whose inputs change from one file per run to N per run (matrix, shards), or that globs artifacts by pattern
- adding a sha/byte-identity guard around an archive or build step (zip, tar, zipapp)
- adding a field to a model whose serialized form is hashed or signed

**Guards**
- Test missing, blank and corrupt inputs and assert the gate fails closed
- Make aggregators assert the expected input count and each upstream job's outcome; simulate one shard producing no file and assert a failure, not a pass
- Build the same source twice at different times and assert equal hashes before shipping a build-then-hash guard (normalize mtimes and order, or hash logical content)
- When extending a hashed model, follow the existing empty-value-drop convention and run the hash-stability regression tests
