# FS-31 · Cache identity or invalidation misses a dependency

A cached value depends on more inputs than its key or tags express: RTK mutations invalidate only their own tag while list, summary or version views also show the field, optimistic patches skip server-computed fields, differing arg shapes defeat dedup, and backend cache keys omit view kind, pagination independence, None-vs-empty, or database identity (one Redis shared by several worktree DBs). Stale or cross-contaminated data appears only after the right sequence.

**Triggers**
- a new mutation or query endpoint in a domain with existing cached views, or 'copy the invalidation list from X'
- a mutation with server-side effects on fields other than the one sent
- introducing a backend cache, or adding pagination/filters to a cached endpoint
- several databases (dev/e2e/worktrees) sharing one Redis with id-only keys
- a CI schema-snapshot or build cache shared across branches whose migration graphs diverge
- a per-run DB dropped and recreated under the same name while a cache namespace is keyed by DB name and row ids
- a list whose rows are created by other actors (bots, CI, workers) while the page is open

**Guards**
- List every field the mutation changes and every cached view that shows it; add each to invalidatesTags and test by reading the view after the mutation
- Reconcile the full mutation response into caches instead of hand-patching one field
- Include every value-shaping dimension in backend cache keys (view kind, filters, DB/env namespace) and test that two variants don't collide
- Reuse existing hook argument shapes so RTK Query can dedupe
- Key snapshot restores by an exact migration-set hash and branch, and purge the whole prefix (not one key) when poisoned
- Flush the DB's cache namespace immediately after every CREATE DATABASE in pool/shard scripts and test two consecutive runs that create the same ids
- For lists written by other actors, refetch on mount/focus or push invalidation; test by creating a row out-of-band and reopening the page
