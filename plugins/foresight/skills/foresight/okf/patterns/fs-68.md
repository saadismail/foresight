# FS-68 · User-facing copy, enum labels or digits bypass the localization layer

In a localized app (i18next t(), Arabic with Arabic-Indic digits) new or extended components render literal English strings, raw enum/data keys (Object.keys, WANT/FIT), SDK-provided strings (RevenueCat priceString) or Intl output directly, or compare a localized options list against an untranslated stored token. Whole components written before the i18n pass never call t(). English QA looks complete; the gap surfaces only when a user reaches that flow in Arabic, one screen at a time.

**Triggers**
- a .tsx file that renders <Text> has zero t( calls, or a JSX text node / prop default is a quoted capitalized English string
- a component renders enum values, object keys or status codes as display text
- a new screen shows a number or price from a third-party SDK (RevenueCat, StoreKit) or formats digits with Intl.NumberFormat
- a picker checks whether a stored raw value is a known option by looking it up in a list of translated labels
- extending a component or screen that predates the app's i18n retrofit
- a next-intl useTranslations(namespace) whose keys were authored under another component's JSON path

**Guards**
- Grep touched and sibling files for literal capitalized strings in JSX and for .tsx files with <Text> but no t( before calling an i18n change done; run the same check in CI or the pre-release checklist
- Map every enum/key shown to users through t() with one key per value; compare canonical tokens, never localized labels (de-localize one side first), and unit-test that a stored canonical value does not produce a duplicate option
- Route every displayed number and store price through the shared localizeDigits()/price component; on Hermes do not rely on Intl numberingSystem options or -u-nu- locale tags, which iOS Hermes ignores
- QA every touched screen in Arabic on device, including sheets and every variant (each paywall gate reason), not only the screen that was reported
- Assert rendered label text, not only testid presence, and lint for translation namespaces with zero matching keys
