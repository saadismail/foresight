# FS-11 · Enumerable scope silently shrinks between ask and done

The scope source is a list (AC items, the sub-surfaces one criterion names, a mock's render functions and interactions, features of the component being replaced, approved-but-unbuilt specs), but the work is checked against a mental summary. Items are dropped, reduced, placeholdered or traded away and the report doesn't say so; the user finds the gap. The same gap appears as substitution: the implementer swaps in a different path or mechanism than the one the user stated, widens a guard beyond the requirement, or treats the reporter's examples as the full extent of an org-wide problem.

**Triggers**
- an AC list with 6+ items, or one criterion naming several surfaces/call sites
- porting from a designs/ mock or reference product, or replacing an existing page/component wholesale
- a redesign that merges fields/filters or refactors shared page state with multiple URL modes
- a broad go-ahead ('lets go', 'do the rest') over several approved items; a trade-off noted only in implementer notes
- the user specifies an exact mechanism or scope (rebuild-only, one agent per location); a guard's docstring reads broader than the requirement; the reporter lists example entities for an org-wide issue
- a store-listing or rebrand task that says 'images' or 'screenshots' (icon, feature graphic and template logos are separate slots); a 'design parity' ask with a design screenshot or jsx available

**Guards**
- Keep a literal AC -> task -> spec checklist from planning through the exit audit
- Diff the build element-by-element and interaction-by-interaction against the mock render function for every view/mode before reporting done
- Before replacing or consolidating UI, list every existing field, filter, affordance and mode and confirm each survives
- Report any deferred, reduced or placeholder item as an explicit scope cut and ask before trading away a capability
- State any deviation from an explicit directive and get one line of confirmation; wire guards against the requirement text, not the helper's docstring; run discovery unfiltered before narrowing to the reporter's examples
- Enumerate every asset slot the store console exposes and every static image a template references, check each against the new brand, and bump cache-busters on swapped assets
