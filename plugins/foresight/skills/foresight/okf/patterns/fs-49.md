# FS-49 · Delete-then-recreate resubmit strands previously posted rows

A resubmit/replace endpoint or rebuild implements 'update' as delete the parent and recreate children from the payload, as QuerySet.set() on an M2M, or as a skip when a value becomes zero. Children linked only by M2M survive as orphans with their posted transaction/ledger-entry legs, prior-version legs stay alive next to the new ones, a classification change leaves the other posting path's legs as zombies, validation runs after the delete, and day rebuilds delete every source type but recreate only some. Single-submit tests pass; the second resubmit, an edit to zero or a moved amount doubles or strands ledger rows.

**Triggers**
- a submit/replace endpoint calls .filter(...).delete() on the parent before recreating children or before serializer validation
- children linked to the parent by M2M rather than an owning FK with cascade; QuerySet.set() on a resync/relink path
- a skip guard (if amt < 0.005: return/continue) inside an upsert-on-key writer
- a mutable classification field (payee.is_employee, check trans_type, payment_type) decides which posting path owns a leg
- a day-level delete-then-rebuild that deletes by date for all source types
- a new report aggregates a child table that resubmits are known to orphan

**Guards**
- Update children in place by natural key (upsert-no-delete) and delete only rows absent from the payload, together with their posted legs, inside one transaction
- Test resubmitting the same entry 2-3 times (including moving an amount between sibling child rows and editing a value to zero) and assert day_delta == 0 and no Expense/Deposit with an empty M2M still holds a live Transaction
- Validate the whole payload before any delete; test that an invalid resubmit leaves the existing record intact
- On a classification change, re-run every posting function gated by that field and clean up the legs of the path that no longer applies
- Before a delete-then-rebuild, enumerate the source types present on the date and exclude any the rebuild cannot recreate (such as an opening-balance transaction); make each atomic unit one (location, day)
- Aggregate child tables through the live parent link, never the raw child table
