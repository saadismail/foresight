# FS-47 · Double-entry leg posted without its offsetting leg

The two legs of one accounting entry are produced by different functions, branches, events or entity save() hooks, each with its own guard: a date cutoff, a payee_type/source_type branch with a fallback on one side only, an early return meant for an unrelated sub-feature, an accrual leg deferred to a later payment event, a counter-leg that only another entity's save() creates, or a leg dated by a different rule than its counterpart. Any input that satisfies one side's condition but not the other's lands a lone leg and imbalances the balance sheet, which surfaces only in reconciliation weeks later.

**Triggers**
- a ledger-posting function from a per-source-type family branches on payee type, source type, payment method or check type
- one leg of a pair is created by a different entity's save() (Check, CreditPayment) or by a later event (payment of a credit expense)
- a guard (early return, date cutoff, print/status gate, amount < epsilon skip) wraps only one of the legs, or sits above an independent sibling computation
- a payment/clearing entity can have zero line items, or a bank categorization has no recognized transfer link
- a new offsetting/suspense leg must net against an existing leg on the same day, or a bidirectional match writes only the counterpart

**Guards**
- Write a balance-invariant test per branch value (each payee_type, source_type, payment linkage, the degenerate empty entity): after posting, debits == credits and both legs share accounting_date and location
- Post both legs from one function under the same guard and the same fallback strategy (both default, or both raise on an unrecognized enum value)
- For accrual-type entities post the payable leg at accrual time and assert a credit expense with no payment yet still balances
- Reject or route to a suspense/clearing account any input with no defined counter-leg (zero-item payment, bank-to-bank without a transfer link) instead of letting it fall through
- Run a periodic audit query for source rows whose expected counterpart (a check record, a ledger entry, a POS purchase entry, a banking ledger entry) is missing, and assert both sides of a bidirectional match end symmetric
