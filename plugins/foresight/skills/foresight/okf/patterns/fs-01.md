# FS-01 · Async client state read at the wrong moment or outliving its scope

Client code reads or captures a value before it resolves, after it goes stale, or from a store whose lifetime doesn't match the component/session: mount-time reads of async hooks, stale-closure read-modify-write toggles and URL patches, out-of-order responses, RTK data vs currentData, module-level singletons, one-shot refs/listeners never reset. Human-speed clicks on a warm cache pass; it surfaces on remount, rapid input, cold cache, StrictMode or the second open.

**Triggers**
- useState/useRef seeded from a hook value that loads asynchronously (permissions, active workspace, query data)
- a handler reads the current selection/URL params and writes back a modified copy, and can fire twice before re-render
- a new async request per keystroke/drag with no generation token or cancellation
- module-level or app-shell singleton store/cache/ref holding per-instance or per-open UI state; dialog stays mounted between opens
- dependent RTK Query hooks where the first arg can change while the second is still fetching; one-shot listener keyed to an event that may already have fired
- a useEffect that calls focus()/scrollIntoView lists a callback prop (onClose) that call sites pass as an inline arrow
- a useEffect/useLayoutEffect reads ref.current to attach a ResizeObserver/IntersectionObserver, gated on a dependency that is not the ref's own attach
- an open menu, popover or dialog rendered inside a subtree that remounts on data or timer changes: TanStack column defs memoized on volatile deps with inline cell renderers, or a dialog inside an empty-state branch its own mutation flips via cache invalidation

**Guards**
- Gate queries on async ids with skipToken; use currentData/isFetching (not data/isLoading) for state scoped to a just-changed argument
- Use functional updates for read-modify-write and compose URL patches into one atomic update; e2e-click two options back-to-back with no wait
- Tag async requests with a monotonically increasing generation ref and drop stale resolutions; test out-of-order responses
- Scope stores to the owning instance and reset state/polling on open, close and route change; test open-close-reopen and a StrictMode remount
- For one-shot listeners/flags check whether the event already fired, reset on re-arm, and add a timeout fallback for any awaited cross-process signal
- Depend imperative focus/scroll effects only on the triggering value (open) and hold callbacks in a ref; type into text fields with keyboard.type per keystroke in e2e, not only fill()
- Attach DOM observers through a callback ref and test that resizing the observed element fires the callback
- Keep column defs and cell renderers stable (volatile values via table meta/refs) and lift dialog open state above data-conditional branches; test by opening the overlay, triggering the data change, and asserting it stays open
