# FS-26 · Boundary values and NULL/join semantics not exercised

Logic is written for typical values and misses empty, zero, single-option, null or absent keys, falsy-but-valid values, timezone shifts, clamps and cap-plus-suffix limits, overlapping conditions, and SQL/ORM semantics such as NULL under exclude(), order_by leaking into GROUP BY, and joins double-counting rows. Fixtures never contain the degenerate case.

**Triggers**
- exclude(field=value) or a filter on a nullable/JSON key; values().annotate() on an already-ordered queryset
- a dict built from query rows then indexed by every possible key; sums over rows reachable through several joins
- if value: on fields where 0/''/[] are valid; Number()/int() on parsed string segments
- a picker that can have exactly one option, date math mixing local and UTC, a permission matrix with 3+ combinations
- fixtures never contain a NULL, zero, negative, net-zero or sentinel row: a nullable boolean filtered with field=False, a nullable FK dereferenced on legacy data, zero-item entities, a sentinel shared by many rows, an as-of date for a cumulative figure
- a feed selector maps over child rows (steps) that share a parent (contact); a 'set once, applies broadly' value (reminder due date) stored on one child row
- tiered rates (day/week/month) priced as the finest tier times a count
- `if e.response:` / `if resp:` on a requests.Response (falsy for any status >= 400) inside an error handler or log statement (recurs even though 'is not None' is listed below)
- value-based redaction or replace-by-value over a bundle that can hold very short values (1-3 characters)

**Guards**
- Add explicit tests for empty, zero, one, null/absent, max-length and cross-timezone inputs
- Use isnull filters for absent JSON keys, clear order_by before aggregating, and dedupe by id across many-to-many joins
- Replace truthiness checks with 'is not None' and validate formats with a strict regex before coercion
- Enumerate every combination of multi-flag conditions and route modes in a table-driven test
- Use exclude(field=True) for nullable booleans; test legacy rows with null FKs and all-empty collections; build report skeletons from the union of per-period rows; compute cumulative adjustments as of the entry's own date
- Test a parent with N>1 children: exactly one card, and the value survives completing the first child
- Write table-driven tests at every tier boundary (7 and 30 days, remainders) against the published rate card
- Add a test that a 4xx error path logs the provider's real response body
- Redact by secret-marked key with a minimum value length, and test with a 1-character value
