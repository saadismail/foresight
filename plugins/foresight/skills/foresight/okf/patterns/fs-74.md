# FS-74 · Fixed lineHeight near fontSize clips Arabic and display glyphs

Text styles pin a numeric lineHeight equal or close to fontSize (9/9, 15/18, 22/26), tuned for Latin text. Arabic fonts such as Cairo have taller ascenders and diacritics, and large display headings put the cap height at the line-box edge, so glyphs are cut. The symptom reads like layout overflow, so the first fixes change flexShrink/flexWrap, and the bug recurs component by component as users find each screen.

**Triggers**
- a text style sets an explicit numeric lineHeight at or below about 1.2x fontSize on user-facing copy in an Arabic-capable app
- a large display/heading style with lineHeight === fontSize
- a user reports text 'clipped' in a pill, badge or name while its container looks correctly sized

**Guards**
- Route text styles through the shared rtlLineHeight() helper (or give at least 1.2x fontSize headroom) instead of literal lineHeight values
- When one clipping bug is found, audit every literal lineHeight in the app once instead of fixing per report
- Before changing layout for 'clipping', zoom into the glyphs in Arabic on device to tell vertical font clipping from overflow
