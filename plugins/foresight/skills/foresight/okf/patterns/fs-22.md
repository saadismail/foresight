# FS-22 · Capability built in one layer but never connected to the next

One layer implements a capability and the adjacent one never consumes it: PATCH exists but no edit UI, backend search/pagination not exposed, a filter param in the cache key but not the queryset, persisted settings the runtime ignores, audit fields not serialized, a cap computed but not enforced, a label prop never supplied, a specialized mutation imported but unused behind a silently succeeding fallback. Each layer's tests pass.

**Triggers**
- the backend accepts params or returns fields the FE component doesn't read or render
- a spec item is a cap, breaker, limit or setting whose enforcement lives in another code path
- a prop/arg/param is threaded through types but its source or sink isn't in the diff
- an unused hook/mutation import, or a control labeled as a toggle with no handler
- a field drives sorting or overdue logic in a selector but has zero JSX usages

**Guards**
- For every accepted param or setting, test that the output actually changes when it is supplied
- Trace each new field DB -> serializer -> FE render (and back for edits) as one checklist
- Test the enforcement branch of any cap/breaker/guard, not only the computation
- Add a render test asserting that the formatted value of every new sort/business field appears on the card
