# FS-05 · Concurrent sessions contend for one local DB, port, cache or CPU

Several agent sessions/worktrees and orphaned processes from earlier runs share the same local Postgres, pytest DB name, ports, Redis and CPU. Connection pools exhaust max_connections, test-DB create/drop races, ports get squatted and kill/cleanup hits the wrong process, so failures look like regressions in the code under test.

**Triggers**
- more than one session/worktree active in the repo and about to run pytest or boot an e2e stack
- e2e backend launched via daphne/runserver without DB_CONN_MAX_AGE=0, or with Silk enabled
- OperationalError 'too many clients' or 'database is being accessed by other users'
- re-running a command that previously timed out or was backgrounded; killing a server by its npm parent PID or lsof -ti :port
- about to fan out more than about three agents that each run full Playwright suites
- sizing batch/fan-out concurrency on a shared ops box; pkill -f by pattern among several agents; a hardcoded test DB name or a leftover test DB from an interrupted run
- running CLI xcodebuild / expo run:ios while Xcode.app has the same project open and indexing
- starting a worktree's dev servers on default ports while the primary checkout's servers are running
- starting a server on a hardcoded port (API :9100, static demo :3000) that an earlier run may still hold; one agent's e2e teardown running while another agent depends on a shared dev/demo server
- a reviewer or a pipelined next-task implementer dispatched with test-run permission into a lane whose implementer is still running pytest on the same per-lane test DB
- parallel lanes inheriting one session scratchpad and writing helper scripts or result files with identical names
- a brief that isolates ports and DBs but says nothing about scratch dirs or pattern kills; a runner that backgrounds servers with a blocking wait and no signal trap
- about to fan out parallel worktree lanes, each with its own node_modules, test DBs and Playwright output, or many idle worktrees already exist
- a lane wrapper passes the test command through to an agent that may drop the -n / --workers cap stated in its brief

**Guards**
- Give every parallel workstream its own PGDATABASE_TEST / e2e DB, explicit free ports and Redis prefix before dispatch
- Boot e2e backends with DB_CONN_MAX_AGE=0 and Silk off; check pg_stat_activity before large runs
- Before re-running, kill prior runner instances by process group and confirm none remain; target LISTEN sockets only (lsof -sTCP:LISTEN)
- Wrap e2e app launches in try/finally, clean temp profiles, and cap concurrent full-suite runs per machine
- Measure one job's peak RSS against free RAM before choosing concurrency; kill by the PID captured at launch; derive the test DB name per session and drop leftovers before --keepdb runs
- Quit Xcode.app (or confirm it isn't open on the project) before CLI iOS builds so the two don't write one DerivedData; read the real error past exit code 65
- Pick a disjoint port range for each worktree before its first server start and record it in its launch config
- Record the PIDs each launch starts (pidfile) and have teardown kill only those; never kill by port range or name pattern in a multi-agent environment; check lsof -i :PORT -sTCP:LISTEN before starting and kill only that stale PID
- Name test DBs per agent, not per lane, and keep profiling middleware (Silk) out of e2e backend settings
- Give each lane its own scratch subdir (scratchpad/lane-X/) in the brief and have scripts assert their own lane id and port before running
- Brief every lane with an explicit ban on pkill -f / killall by script name; kill only PIDs recorded in the lane's own pidfile
- Write trap-based teardown (TERM, grace, KILL) with wait $pid from the start and test it by interrupting a run and checking ports are freed
- Run df -h before fan-out and budget about 2 GB per worktree; between waves delete merged lanes' worktrees and node_modules and drop their test DBs
- Enforce per-lane worker caps in the launcher's environment or wrapper (PYTEST_ADDOPTS with -n, a Playwright workers variable), not only as brief text, and refuse runs that exceed them
