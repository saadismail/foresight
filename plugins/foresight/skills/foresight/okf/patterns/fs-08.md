# FS-08 · E2E locator or assertion coupled to incidental page content

Specs locate or assert through things that are not unique or stable: copy text, unscoped getByText/role names shared with breadcrumbs, headings or a confirm dialog's trigger, substring or unanchored matches, row position/index 0 in accumulating shared data, exact computed-color strings, magic numbers, sr-only nodes. They pass once, then break or hit the wrong element as copy, data volume or browser serialization changes.

**Triggers**
- the target text/name also renders in a breadcrumb, heading, sidebar, or the button that opened a confirm dialog
- locator uses .first(), results[0], nth row, or a regex/name without anchors or exact:true
- assertion on literal UI copy, raw API numbers, exact rgba() strings or a duplicated constant
- spec expects a newly created row to be visible without searching for it
- a positional assertion on a shared append-only registry; a repeated component mounted with identical testids
- a Maestro assertVisible/assertNotVisible with a bare literal string on a React Native row that mixes a button and text
- a computed-style assertion reached through locator('..') from a leaf-input testid; a class-based locator inside a container whose child components render the same class; money assertions with the currency glyph baked into the expected string
- a Maestro tapOn by visible label text for an input on a form where the field can sit off-screen behind the keyboard
- pagination is added to a list or the seed grows, while specs or helpers pick results[0], the first row, or expect a row on page 1
- toHaveURL with a $-anchored regex on a route that can redirect to a default child or carry tab/filter state in the query string
- navigating between two detail views of the same kind where the old panel stays mounted until the new data loads

**Guards**
- Scope locators to the owning container (dialog, row, card), go through the page driver's testids, and pass exact:true for role names
- Find created entities by a unique generated identifier via search/filter, never by position
- Assert through the same formatter/constant the UI uses; parse computed colors for oklab/oklch/rgb forms
- Scope console-error assertions to the feature and keep known-noise allowlists in the shared helper
- Dump the device accessibility hierarchy and confirm the matcher actually matches (use a regex for RN-flattened labels such as ', Add email') before trusting a RED
- Locate the exact element the CSS rule selects; scope class locators to direct children (> .cls); assert the number and the currency mark separately
- Tap inputs by testID/accessibilityLabel, not label text, and assert the field's value after each input step
- Find the target row by id, search or filter through a driver that pages, never by position or page-1 membership; re-run specs after any seed growth, sort or page-size change
- Assert a page-ready testid or match pathname only, tolerating redirect segments and query params
- When a spec comment claims a row is unique ('only one active sprint'), check whether the list paginates and seed 26+ extra rows once to prove the locator still finds it
- Wait for the new entity's identity marker (its id or tag) before acting, and scope locators to a container keyed by that id
