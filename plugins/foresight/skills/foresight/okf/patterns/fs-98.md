# FS-98 · Desktop main-process windows, listeners and IPC state tied to one happy-path lifecycle

Electron main-process code assumes one window that lives as long as the app and a renderer that always answers. Listeners bind to the first window only, a lazy window accessor respawns windows during shutdown, fs watchers keep the process alive after quit, a 'recording' flag is cleared only by the renderer's success message, callback-contract handlers await with no error path, hidden windows have their timers throttled, isLoadingMainFrame is still true inside did-finish-load, a best-effort startup step aborts boot, the app's own HUD is still composited when frames are grabbed, and secondary windows sync auth but not the state that depends on it (or follow every later change). The single-window happy path works; quit, close-to-tray and reopen, renderer crash, a denied permission or a second window breaks it.

**Triggers**
- main-process code attaching listeners, watchers, timers or IPC state to a BrowserWindow, or a change that lets windows close and be recreated (tray/dock keep-alive)
- a state flag set on start and cleared only by a message from a renderer or another process
- a callback-style Electron handler (display-media, permission) that awaits or has a deny/cancel branch
- a timer, recorder or countdown hosted in a hidden or background window; a screen grab while the app's own HUD or hint windows may be visible
- a filesystem/registry step in the startup path; navigation code that branches on isLoadingMainFrame from load events
- a secondary window that mirrors main-window state through storage events or IPC

**Guards**
- For each main-process resource (window, listener, watcher, timer, IPC flag), list the events that end or recreate it (will-quit, close-to-tray and reopen, render-process-gone, hide) and test each: listeners re-bound on recreate, watchers closed on will-quit, no lazy respawn after before-quit, state back to idle on renderer death
- Callback-contract handlers use try/finally so the callback fires exactly once, use a deny shape the pinned Electron major accepts, and are tested with process.on('unhandledRejection') failing the test
- Windows that own timers set backgroundThrottling:false; hide the app's own chrome and wait for the compositor (or setContentProtection) before the first getSources
- Wrap each best-effort startup step in its own try/catch and test with a throwing stub that the main window still opens; defer one tick from did-finish-load before reading load state
- For cross-window sync, list every piece of state the secondary window derives from the main one (auth, workspace, dependent pickers) and decide per piece when it follows (sign-in only vs every switch); e2e sign-out/sign-in in window A and assert window B
