# FS-107 · New obligation or notification enabled by default for existing callers

A finalize step, a new notification type or a new background check becomes active by default for every caller or existing user: a pending obligation (an expected upload, an acknowledgement) that a timer later escalates, or a new event that a stored wildcard preference or master switch opts everyone into. Callers that never intended to take part create stalled records, false alarms and auto-filed tickets, or existing users start receiving messages they never asked for. Opt-out defaults hide it until the timer fires or the deploy reaches production.

**Triggers**
- a finalize, close or submit step that creates a pending record a sweeper later escalates or notifies on
- a boolean like *_expected / *_required defaulting to true, or inferred from weak signals
- a new notification or event type evaluated against stored wildcard or master-switch preferences ({*: true})

**Guards**
- Make the obligation opt-in by the caller that will fulfil it; default off
- Test that the plain path (no opt-in) creates nothing pending and never escalates; a late fulfilment may reopen it
- Test an existing user's stored preferences (wildcards, master switch) against the new event and assert the documented default wins
