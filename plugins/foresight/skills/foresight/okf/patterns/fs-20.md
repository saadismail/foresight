# FS-20 · Concurrent sessions share one working tree or branch

Several agent sessions edit, stash, reset, checkout or commit in the same primary checkout or branch. Uncommitted work is destroyed or swept into another session's stash or commit, HEAD moves underneath a session, and partial commits leave the committed tree referencing files that exist only in someone's working directory.

**Triggers**
- git status shows dirty files from unrelated feature areas
- about to edit, stash, reset or checkout in the primary checkout while other sessions are active
- a second agent dispatched into a worktree another agent is still editing
- about to push/deploy a branch several sessions committed to
- a shared dev box whose checked-out branch and .env other people change; a shared cross-session memory file
- cherry-picking or committing on a shared main tree that other live sessions push to; resuming with 'continue' after a gap in a tree the user also operates on
- a pathspec commit that fails a different pre-commit hook on unrelated files at each retry; a build failure that names files you never touched

**Guards**
- Work in a dedicated git worktree per session/agent; never bare git stash/reset in a shared directory
- Commit small increments immediately, stage explicit paths and diff --cached against the intended list
- Before deploying, build/test a fresh clean checkout of the committed HEAD
- Delete files only by exact name after checking git status for tracked vs untracked
- When a shared box starts erroring mid-task, check its git branch and .env DB target before retrying; re-read shared files immediately before writing
- Before every commit or cherry-pick in a shared tree: git fetch, confirm the current branch is the task's, and diff for changes you didn't make; after a concurrent merge grep for duplicate top-level declarations before trusting the Metro bundle
- Suspect a concurrent writer (pre-commit stashes unstaged files); check git status for files you didn't touch before trusting a build failure, and move the work to a worktree
