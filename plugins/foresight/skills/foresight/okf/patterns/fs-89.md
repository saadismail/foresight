# FS-89 · Derived counts, id lists and census docs not updated with their source collection

A source collection (benchmark cases, a ratchet/known-gap file, a retired-pin set) is mirrored elsewhere: generated coverage docs, a prose doc quoting its total, hardcoded `== {ids}` test literals, and a second id list in a DB-gated test. Changing the source leaves those copies stale. The scoped local gate doesn't cover them, so the drift shows up only in the full suite or in a CI-only job, often after review has passed.

**Triggers**
- a change adds, removes or moves an entry in a source collection (benchmark case, ratchet/known-gap list, retired-pin set, registry) that docs or tests cite by count or id
- the repo has generated coverage/census docs or a prose document quoting a total, with count-gate tests over them
- a test asserts == {literal set of ids} or an exact count over a collection that is expected to grow
- the gate that checks those artifacts runs only in CI (a Postgres-gated job) or in the full suite, not in the task's scoped selection

**Guards**
- After changing the source collection, run the doc/census generator, its count-gate tests and any doc checker (whitepapercheck) locally, then the full suite, not only the scoped selection
- Grep tests/ and docs/ for the changed case id and the old count literal, including tests skipped locally because they need a DB, and update every hit in the same commit
- Replace duplicated id sets and quoted totals with values derived from the source file, or assert a relational property (retired == declared-gone) instead of an exact literal
- Put a local, no-DB check over every derived artifact (pre-push or unit test) so drift fails before CI
