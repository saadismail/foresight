# FS-88 · Mobile OAuth client bound to a signing key or cloud project other than the one real installs use

Google Sign-In on Android binds the OAuth client to the package name plus the SHA-1 of the signing certificate, and requires that Android client to live in the same Google Cloud project as the webClientId used as the token audience. With Play App Signing, store installs are re-signed with a Google-held app-signing key whose SHA-1 differs from the local upload key, and an Android client created in another GCP project never matches the audience. Sideloaded and debug builds work; store installs fail with DEVELOPER_ERROR, which users report as a crash.

**Triggers**
- enabling Play App Signing on an app that uses Google Sign-In or another SHA-1-bound Google API (Maps, Firebase)
- creating a new Android/iOS OAuth client while the webClientId was created earlier, possibly in a different GCP project
- Google Sign-In works on a sideloaded or debug build but a Play-installed build shows DEVELOPER_ERROR or 'not configured'

**Guards**
- Record the GCP project id of the webClientId and create every Android/iOS OAuth client in that same project; check it before registering any SHA-1
- Register the SHA-1 of every key that signs a build users run: debug keystore, upload key and the Play app-signing key (Play Console App integrity, or apksigner verify on a Play-generated APK), as soon as Play App Signing is enabled
- Test sign-in on a build installed from the Play internal track, not only a sideloaded APK, before promoting
