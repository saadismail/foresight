# FS-80 · Temporary debug bypass or backdoor left in a shipped auth path

A shortcut added for local testing, such as an impersonation hook that signs in with a token read from .env or a `false &&` short-circuit on the email-verification gate, is gated on a token's presence or on nothing at all instead of __DEV__ plus a default-off flag. It rides along into store builds and production and silently disables a security control until someone notices.

**Triggers**
- an auth/verification condition gains a literal true &&/false && prefix, or a TEMP/DEV/BYPASS/HACK comment
- the app entry (_layout.tsx) imports a debug module that reads a secret or token from EXPO_PUBLIC_* env
- about to cut a store release after a debugging session that touched auth

**Guards**
- Gate any dev-only auth behavior on __DEV__ plus an explicit env flag that defaults off, never on a token's presence
- Before every release grep the diff for true &&/false &&, TEMP/BYPASS markers and EXPO_PUBLIC_*TOKEN reads, and grep the release bundle for the debug module's marker
- Keep a test asserting the security gate rejects the unverified/unauthorized case
