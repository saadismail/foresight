# FS-73 · Native build started without a host preflight (SDK path, UTF-8 locale, disk, gitignored config)

Local iOS/Android builds depend on host state that a fresh shell, a fresh worktree or a cache wipe removes: ANDROID_HOME and android/local.properties sdk.dir (deleted by expo prebuild --clean), a UTF-8 LANG/LC_ALL for CocoaPods pod install, free disk after repeated archives fill DerivedData/Archives, and gitignored native config (google-services.json, GoogleService-Info.plist, .env) that exists only in the main tree. The build fails minutes in, often in the middle of a release pipeline.

**Triggers**
- first Android/iOS build in a session or in a fresh worktree, or right after wiping DerivedData, ios/build or Expo caches
- about to run expo prebuild --clean or pod install from a non-login or background shell
- several archive/build cycles already ran in this session
- the app depends on gitignored native config files
- more than two or three full native rebuilds planned in one session on a laptop disk; an opaque Gradle daemon or build-tool error mid-session

**Guards**
- Run a preflight before every native build: ANDROID_HOME/adb set and android/local.properties has sdk.dir, LANG=en_US.UTF-8 and LC_ALL=en_US.UTF-8 exported, df -h shows headroom, and every required gitignored file exists
- Make that preflight (including restoring local.properties after prebuild --clean) an explicit step of the release script, not a manual afterthought
- Copy every gitignored config the build needs from the main tree into a fresh worktree before its first build
- Clear stale DerivedData and old .xcarchive files between repeated archive attempts
- Run df -h before each rebuild and clear regenerable caches (DerivedData, Gradle build outputs) between builds, not after a failure
