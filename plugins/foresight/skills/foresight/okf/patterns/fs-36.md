# FS-36 · Ambiguous or constraint-bearing ask resolved without asking

An instruction admits more than one reasonable model (which surface or component, per-project vs central roles, deployment-wide vs per-tenant keys, which of several workspaces named after the product, inline vs listed attachments) or collides with an earlier decision or constraint (a rejected design, a unique(kind) constraint, RBAC on the guarded field), and the agent silently picks the convenient reading and builds a lot on it.

**Triggers**
- the request names a generic surface/component that maps to several implementations
- two standard data-ownership models both fit the wording
- the instruction contradicts a documented rejected approach or an existing uniqueness/permission constraint
- an irreversible bulk write targeted by an informal name, or 'copy the front end from repo Y'
- an ambiguous domain term that already names a distinct feature; the orchestration/visibility model for a multi-hour fan-out
- choosing the sort direction/tiebreaker for a to-do-like feed; a complaint that a prefilled field 'shouldn't be editable'
- building backend endpoints for a design-parity feature before the frames are available; replacing a free-text field with a fixed-enum picker; a list's primary decision (accept/reject) reachable only from a details modal
- fanning out UI or auth work to parallel lanes before the user has picked the approach

**Guards**
- State the chosen interpretation and the alternatives in one line and ask before building, or ship one small representative slice first
- Re-read earlier rejections/ADRs and the constraints of the model the feature layers onto; spike the blocking assumption
- Confirm the exact target (id, domain) before irreversible writes
- Ask whether a prefilled scaffold value should stay locked or disappear; confirm FIFO vs newest-first for task lists and write the ordering test first
- Keep the API shape provisional until frames are captured; ask whether the value space is really closed (offer Other plus free text); ask whether the primary decision must be a row action
- Lock design and auth decisions with the user before fanning out lanes; superseded lanes are the cost of skipping this
