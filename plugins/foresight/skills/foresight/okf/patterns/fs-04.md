# FS-04 · Tests pass without proving the requirement

A green test cannot fail for the defect it is meant to catch: only the happy path or one of N call sites/variants is exercised, the oracle is derived from the code under test or an assumed policy, the spec adds steps the criterion doesn't allow, it asserts presence instead of content, or it encodes the current buggy behavior. Coverage numbers and green runs create false confidence until a user or reviewer hits the gap.

**Triggers**
- a helper/param/pattern used at several call sites or view variants while the test plan names one
- an acceptance criterion names literal text, an immediate UI change, several surfaces or several close methods
- an RBAC test strips a role instead of one codename, or the permission helper has OR/tiered/owner-bypass branches
- expected value computed by the same function under test, or a test comment carving out a known bug as expected
- an except/error branch no existing test reaches
- a spec line enumerates cases with 'or', or a test claims to exercise all N legs/branches/reasons
- a unit test reads component source text or asserts a function name with toMatch(/name/); a sync pipeline carries several entity types (parent plus attached photos, voice notes, tags) through separate push/pull branches
- action buttons in a fixed-width table row covered only by a click (Playwright click auto-scrolls); a spec asserting literal copy not found in the requirement it cites
- a sort/order test whose fixture's insertion order already resembles the expected order; a .map(...).sort(...) chain whose comparator reads fields the mapped shape dropped
- a new branch beside an existing path, a fixpoint while-changed loop, a resolver handling several AST shapes (f-string and concat), or a benchmark case labelled with a dimension (enum value, reorder) the pipeline may not capture
- a plan that defers running e2e specs to a final lane, or parallel lanes merging into one integration branch
- a dispatch that lists required behaviours or negative tests (audit fields, soft-delete, tenancy, sibling project, bad id) in prose
- a test.skip conditioned on seed data, or a smoke test whose only assertions are URL shape and a global object
- the same rule text duplicated in a doc or prompt and in a server constant

**Guards**
- Build a criterion/risk -> test table before declaring done; one test per call site and per view variant, including empty/loading/error/keyboard states
- Make each acceptance e2e perform exactly the criterion's user action and assert rendered content, not element presence; an extra needed step is a product gap to report
- Derive expected values from independent fixtures and cite the spec section for policy/security assertions
- For permission tests read the view's permission helper and strip exactly one codename; cover OR and prerequisite branches
- Force every error branch once and confirm the test fails with the fix reverted
- Assert the count of legs/branches actually exercised and the exact reason string per case; build RED tests from the exact prod entity state, not a simplified repro
- Assert observable output, never source-grep; require one cross-device round-trip test per synced entity type, not only the primary one
- Assert toBeInViewport or a bounding box for row actions and review a full-width screenshot; source every literal copy assertion from the cited requirement or design, and flag it for clarification if absent
- Give every ordering test a fixture whose insertion order contradicts the expected order, so a no-op sort fails
- Mutation-test the new code before done: force the branch condition (if False:), make the loop single-pass, swap before/after fixtures or remove a different enum value, and confirm some test fails; read back written artifacts and assert on parsed content, not path or existence
- Each parallel lane runs its own e2e specs and scoped tests on its own branch before merging into the integration branch; never defer all e2e execution to a final lane
- Turn every behaviour a dispatch lists into named test stubs the implementer must fill, and check the names exist before accepting the task
- Replace data-dependent test.skip with a fixture that creates the case; count a skipped test as missing coverage
- Assert every copy of a duplicated rule (or derive one from the other) and mutation-probe by rewording each copy
