# FS-16 · Client-supplied id resolved outside the tenant-scoped queryset

An endpoint resolves a client id (list filter, nested/link route, second related id, bulk id list, polymorphic owner, reparent target, team/reviewer ids) via an unscoped get/filter, checks only one of several ids, or authorizes on the first row and writes to all. Scoping on the parent route or a sibling endpoint is assumed to cover it. Happy-path tests pass; cross-tenant tests are missing or arrive at the exit audit.

**Triggers**
- the endpoint accepts <x>_id, <x>_ids, owner_type/owner_id, or a target parent/container id
- a bulk endpoint authorizes once, then loops or writes over an id list
- a new nested, link or relation route under an already-scoped resource
- fixing an unscoped lookup in one views file while sibling files (import/export/bulk) share the pattern
- an aggregate/summary computed over a wider population than the viewer's visible scope
- an update serializer with fields='__all__' on a location/org-scoped model; a location header read with headers.get on a nullable FK; one payload carrying several client-controlled FKs
- a serializer write helper accepts tag_ids/uuid lists and resolves them with Model.objects.get(uuid=...)
- a scoped/restricted code path calls the admin/full repo method and destructures only part of its result

**Guards**
- Resolve every client id through Model.objects.for_user(user) (get_object_or_404 on the scoped queryset); never fetch-then-compare
- Write the foreign-workspace/foreign-project negative test (404 for both human and bot callers) in the same commit, before implementing
- In bulk endpoints scope the write queryset itself and validate all ids share one parent
- When fixing one lookup, grep sibling views for get_object_or_404(Model, pk=...) and unscoped .filter(pk__in=...)
- Pop scoping FKs in update(), 400 on a missing scope header, and parametrize scoping tests across every sibling endpoint and every client FK on the payload
- Resolve uuids through the owner/org-scoped queryset inside serializer write helpers too, with a foreign-tenant uuid test
- Give the scoped path its own narrow query and add a repo test asserting the exact columns/row shape it fetches, so PII creeping back fails
