# FS-37 · Authorization decided on a proxy instead of the real identity or entitlement

Access checks rely on something that correlates with the right answer but isn't it: a stored foreign id instead of current membership, single-use codes not bound to the requester, display names/trigger words or comment text instead of the authenticated author, unverified email for cross-system identity, codenames shared by bots and humans, RLS bound to workspace instead of viewer, null === null while auth loads, exact row ownership instead of the tenancy boundary, manage granted without its view prerequisite.

**Triggers**
- minting a credential/session or redeeming a code; matching identities across systems
- a gate for a human action on an endpoint also reachable by bots/service accounts
- a trust signal derived from content patterns or display fields
- a permission comparison using optional chaining, an RLS policy on a membership table, or a backfill granting codenames
- a permission pre-flight classifies a write (fields changed, create vs update, delete) separately from the upsert that performs it; a test-only endpoint gated by a docstring
- a new service/machine-identity auth path reuses a TTL-cached user-state helper built for login sessions

**Guards**
- Test the negative actor explicitly: revoked member, bot token, another session's cookie, unverified email, auth still loading
- Give non-human actors dedicated least-privilege roles and exclude them from human pickers and approval gates
- Resolve senders by tenant-scoped secret and authors by authenticated identity, never by text or display values
- Grant view prerequisites alongside manage codenames and test the role end to end
- Derive the classification from the same DB lookup and field set the writer uses, keep the check inside the shared write helper, and test fabricated ids, uncompared fields and content swaps; gate test-only endpoints at runtime
- Check high-privilege service tokens against fresh state per request (or invalidate on deactivation) and test that deactivating the account makes the very next request 401
