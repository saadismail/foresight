# FS-105 · Unattended agent fleet loses work at runtime boundaries with no durable replay, liveness sweep or idempotent recovery

A fleet of coding bots runs overnight: a server wakes each bot through a chat gateway, the bot runs a capped agent session in a worktree and reports back over one HTTP callback. Every boundary is fire-and-forget. A config or system-prompt re-render restarts the gateway and its drain drops inbound wakes with no replay; a 502 on the result callback leaves the session marked running and its slot held for an hour; a run hits its turn cap and waits for a human nobody is watching; the sweeper keeps retrying a known-broken path and exhausts its retry budget minutes before the fix lands. The human then recovers by hand (unassign/reassign loops, hand-written watchers), and non-idempotent recovery over-dispatches work that was already woken. Throughput is set by how fast someone notices, not by the bots.

**Triggers**
- bots woken by chat messages or webhooks with no server-side record of unacknowledged wakes
- a run reports completion through a single HTTP callback with no retry, heartbeat or stale-slot reaper
- a server-side change (system-prompt re-render, config) that restarts the bot gateway while lanes are live
- unattended agent runs with a turn or budget cap below the task size
- recovering lost work by toggling assignment or status in a loop
- deploying a fix to a path an automated sweep or retry loop is still hitting
- an overnight or multi-hour fleet run supervised only by a human or by ad hoc watchers

**Guards**
- Before the first unattended night, make every hop durable: wakes queued server-side and replayed until acknowledged, result callbacks retried, live runs heartbeated, and a timer sweep that reaps stale slots and re-wakes lost work
- Recovery must be idempotent: re-wake only items confirmed lost through an explicit re-wake call, never by unassign/reassign loops; assert the wake count stays under the lane cap
- Auto-continue runs that stop on a turn or budget cap up to a lane budget, then escalate to a human instead of idling
- Pause the sweep or reset its retry counters before deploying a fix to the path it retries
- Run one supervision loop on a schedule (launchd/systemd or a scheduled agent) that checks every lane's state, heartbeat age and queue, instead of hand-written watchers per incident
