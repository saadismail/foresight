# FS-42 · Third-party system semantics not honored

Integrations wrap an external API or platform using the obvious happy-path semantics: single-page list calls, .json() on a 204, a whole status code treated as idempotent, unguarded None returns, full GET/PUT to flip one flag, unverified trigger/delivery conditions, unknown network reachability, auth-method invariants. Mocks mirror the assumption, so it fails only against the real service.

**Triggers**
- a new client method for a third-party list/create/update endpoint
- a webhook/bot integration with delivery or trigger conditions, or a push to a service whose host is unstated
- provisioning accounts or changing auth methods in an external system
- uploading a large binary (AAB/IPA over ~50MB) through googleapiclient/httplib2
- a poll/settle parser or error reader written from a vendor integration guide; a webhook-only payment rail (bank wire, virtual IBAN) handled with the redirect rail's correlation key; synthetic identifiers generated for a provider field
- a Play Publisher edits.commit or App Store Connect reviewSubmissions call scripted for the first time, or for an app's first-ever submission
- an integration needs two same-vendor credential types (GitHub OAuth App vs GitHub App); pinning an input on a third-party CI action to remove its network call
- a cluster bootstrapped with a placeholder pull secret, followed by an in-cluster build (BuildConfig / oc start-build), dynamic PVC provisioning, or any platform pod restart after a DiskPressure image GC

**Guards**
- Read the provider docs for pagination, empty bodies, error ids, partial-update endpoints and trigger conditions, and write them down
- Contract-test with recorded real responses: 204/empty body, page 2, the specific error body, None
- Confirm network direction and reachability before choosing push vs dial-out
- Use a chunked resumable MediaFileUpload with a timeout of at least 600s and http.follow_redirects = False, and test with a real full-size artifact
- Hit the live/sandbox endpoint once and assert the real payload shape and error-key casing; write the webhook test from a notification payload that carries no internal payment id; generate synthetic ids to the provider's documented format and test that format
- Submit an app's first-ever version through the store console (it names the real blocking field); retry a Play commit once with changesNotSentForReview toggled on the 400 naming it, and log which branch ran
- Name each credential type by exact product, settings URL and the capability it serves before asking the user; read the action's action.yml/entrypoint to confirm which code path an input actually skips
- On a placeholder-secret cluster treat every platform feature whose images come from the authenticated registry as untested: check builder/CSI image registries first, plan an external build (podman) and static/hostPath volumes up front, and after any DiskPressure or eviction event confirm CSI, registry and ingress pods are Running before relying on them
