# FS-71 · Store build inputs taken from local state instead of asserted against the release target

A TestFlight/App Store/Play build takes its marketing version, build number, branch and API environment from whatever the local tree holds: app.json's version (already approved, or its train closed after READY_FOR_SALE), a build number left from an earlier pre-fix build, the branch a shared working tree happens to be on, and a .env EXPO_PUBLIC_API_URL still pointing at staging. The archive/upload fails late and costs a full re-archive, or it succeeds and ships the wrong code or backend under a version the user is told is live.

**Triggers**
- starting a release pipeline from app.json's version/buildNumber without querying App Store Connect or Play first
- app.json already carries an uncommitted build-number value before a release run, especially after an interrupted or resumed build
- the previous marketing version is approved or READY_FOR_SALE and only the build number changed
- a release build runs in a shared working tree or right after switching branches, with .env edited independently of the branch
- the API URL lives in both eas.json env blocks and a .env/.env.local read by custom release scripts; a release script exports EXPO_PUBLIC_* vars one by one (grep/cut) instead of sourcing the env file

**Guards**
- Before archiving, query ASC appStoreVersions/builds (and Play tracks) for the highest approved/READY_FOR_SALE version and highest build, and bump the marketing version strictly above any closed train
- Mint a fresh, monotonically unique build number per pipeline run (for example a timestamp) instead of trusting app.json
- Begin every release script with an explicit checkout of the named release branch and print the HEAD SHA
- Fail the build when EXPO_PUBLIC_API_URL (or any other baked-in env) does not match the production host for a store-bound build
- Before saying 'live', confirm the exact build number/commit attached to the live store version
- Keep one source for baked-in env and run the placeholder guard on every build path (EAS profiles and local scripts)
- Source the full env file in release scripts and assert after the build that the bundle contains every required EXPO_PUBLIC_* key
