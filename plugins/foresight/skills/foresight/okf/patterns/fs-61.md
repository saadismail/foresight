# FS-61 · Startup path echoes production credentials into captured output

Settings/startup code prints credentials fetched from the secret manager, and a shared ops box's login-shell profile echoes the prod DB credential as a banner. Any SSM, CI or agent command run through manage.py shell or a login shell (bash -lc, sudo -i, ssh with a profile) captures the secret into logs and transcripts. The trap is known and noted in memory but not fixed, so it recurs on every remote-ops task.

**Triggers**
- about to run a command on a remote box via a login shell, sudo -i, or manage.py shell
- settings/startup code logs or prints resolved secrets
- memory notes a credential-echo trap on a box you are about to use

**Guards**
- Invoke remote commands with a non-login shell (bash --noprofile --norc, no -l/-i) and prefer management commands or script files over manage.py shell
- Grep settings/startup code and the box's shell profile for print/log/echo of secret values and remove them at the source; rotate any credential that appeared in output
- Track the leak as a blocking ops item, not a memory note, and scrub secret-shaped strings from output before surfacing it
