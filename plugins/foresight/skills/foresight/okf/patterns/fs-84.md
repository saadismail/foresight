# FS-84 · Dependency or toolchain change not resolved against what actually installs and runs

A package bump, override, version pin or tool-command migration is written as intent and never checked against the resolved result: a `>=` override lets pnpm jump a major version past the consumer's range, the pnpm that corepack resolves needs a newer Node than .nvmrc pins, a bump of the Playwright test package needs its matching browser binaries, and replacing `next lint` with `eslint .` silently widens the linted tree. The lockfile and the first run look fine until a fresh host, a fresh environment or a second verification pass hits it.

**Triggers**
- adding a pnpm/npm override or resolution for a security patch
- bumping the Playwright test package, Next, ESLint or another tool whose runtime assets or config format are coupled to its version
- provisioning a host where Node/corepack is installed separately from the repo's .nvmrc and packageManager field
- replacing a framework-scoped command (next lint) with a bare tool invocation (eslint .)
- removing a package from requirements to escape a native-extension crash (cryptography SIGILL on an arm64 VM) while another installed package still imports it transitively (pymysql _auth)
- a major-version upgrade of an ORM or codegen tool whose migrate step may no longer run generate

**Guards**
- Write overrides as a caret range within the patched major (^4.3.2) and confirm the resolved version with pnpm why or the lockfile before committing
- Pin packageManager explicitly and check that .nvmrc's Node satisfies the engines of the package manager and tools before provisioning
- Make `playwright install` for the pinned version part of the bump commit's steps and of every fresh environment's pre-e2e setup; print tool versions before trusting lint/typecheck output
- When migrating lint or type commands, re-create the old scope with explicit ignores and diff the error count against the pre-migration baseline
- After removing a dependency, pip show / pip list inside the built image to confirm it is gone and run a bare import smoke test in a throwaway container on the target arch
