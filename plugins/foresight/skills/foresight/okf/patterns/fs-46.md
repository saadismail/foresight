# FS-46 · Stage branch merged into a feature branch or promotion hop bypassed

In a multi-stage promotion chain (feature -> test -> dev -> staging -> main, with main backflowed down), a conflict or 'catch up' is resolved by merging a shared stage branch into the feature branch, cutting the branch from a stage, clicking GitHub 'Update branch', or pushing straight to a stage or main. The feature then carries the stage's unmerged backlog, so every later promotion PR drags dozens to hundreds of unrelated commits and conflicts. Separately, an unmerged or silently failed backflow breaks the 'target contains main' invariant, so PRs show phantom conflicts and pollution that get 'fixed' on the wrong branch.

**Triggers**
- a promotion PR reports a conflict, or its diff/commit count is far larger than the commits you authored
- about to run git merge origin/test|dev|staging (or GitHub 'Update branch') on a feature branch, or to branch from anything but origin/main
- one feature branch feeds several promotion targets that have diverged from each other
- about to push directly to a shared stage branch or main instead of opening the promotion PR, or to close a hop's PR and rely on backflow
- a backflow PR (main -> dev/test/staging) is open, failed, or blocked by branch protection

**Guards**
- Before opening or fixing a promotion PR: git merge-base --is-ancestor origin/main <target> (target contains main) and merge-base(<target>, <feature>) == origin/main tip; if not, merge or escalate the backflow gap instead of touching the feature branch
- Never merge a stage branch into a feature branch; resolve conflicts by rebasing or cherry-picking only your own commits onto the target tip, then compare authored-commit count with git rev-list --count origin/main..HEAD and read git diff --stat main...branch
- Cut every feature/fix branch from fresh origin/main; when a branch feeds several targets, rebase onto their common ancestor and check a clean merge-tree against each target
- Use the promotion PR for every hop (no direct pushes, no skipped hops); after a backflow or force-push, close/reopen open PRs so GitHub recomputes their base
- Add a CI check that fails any feature branch whose history contains a merge commit from a stage branch
