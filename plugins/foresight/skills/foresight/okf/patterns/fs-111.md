# FS-111 · Branches merged inside a worktree that a running dev stack serves

The integration worktree is also the directory the shared dev stack (backend autoreload, frontend dev servers) runs from. A lane merge with a conflict, or a half-applied rebase or cherry-pick, writes conflict markers or partial code into files the running servers hot-reload, so the shared stack crashes for every agent verifying against it until the merge is resolved.

**Triggers**
- one worktree is both the merge target for parallel lanes and the cwd of `runserver`, `next dev`, `vite` or similar
- merging lane branches that touched the same files (serializers, shared email/render helpers, message catalogs)
- running `git pull`, `rebase` or `cherry-pick` in a checkout whose servers other agents are using for verification

**Guards**
- Keep the served tree separate from the merge tree: merge lanes in an integration worktree no server runs from, run the scoped tests there, then `git -C <served> merge --ff-only <branch>` (gate-enforced: `fs.py gate commit` refuses merge|pull|rebase|cherry-pick|am in a checkout a listening process runs from)
- Dry-run every lane merge first (`git merge-tree --write-tree HEAD <branch>`); resolve conflicts in the lane's own worktree, never in a shared one
