# FS-23 · Shared identifier changed or claimed without enumerating its users

A name or contract used across the codebase (route path, testid, barrel export, codename, query-param key, RTK endpoint name, function signature, row-dict schema, global client config, shared primitive default) is renamed, extended or newly claimed, and only the obvious consumers are updated. Hardcoded strings in other components, tests, exporters, nginx or parallel workstreams keep the old meaning or collide.

**Triggers**
- renaming a route, testid, export, codename or label
- adding a query-param key, RTK endpoint name or URL path in a shared namespace (router, nginx, apiSlice)
- adding a parameter or field to a function/row dict consumed elsewhere; changing a shared primitive or global client default for one feature
- a form-state path or local name reused for a second meaning (row id field, handler param shadowing a prop); a new package named like an existing module; a changed sentinel value; a list repointed to a new entity
- an infra migration stops or replaces a VM, zone or IP that deploy/ops scripts reference by name
- an e2e driver references a testid string with zero matches in src/; a copy/label rename done only in message catalogs
- lane-0 / shared tooling for parallel lanes picks a name (build dir, port, env var, fixture path) without checking the repo's existing convention, so every lane inherits the churn
- a shared pure helper's return shape changes (one array split into two) while a parallel branch also consumes it, and git reports no conflict

**Guards**
- Grep the whole repo (src, tests/e2e, helpers, docs, nginx conf) for the old and new identifier before and after the change
- Reference routes and codenames through shared constants and add a registry-vs-usage contract test
- Change shared primitives via a new variant/prop rather than the default
- Run the real build (npm run build) after any rename
- Grep the whole repo (deploy/, scripts/, docs) for old instance names, zones and IPs in the migration change and smoke-run the deploy right after
- Add a check that fails on driver/spec testid strings with no match in application source; grep e2e/ for the literal old copy, not only messages/*.json
- Before merging a helper contract change, grep every call site across open branches and add a characterization test per consumer
- Lane-0 tooling: grep the repo (configs, .gitignore, tsconfig includes) for the existing name of every dir, port or env var before choosing one; resolve lane0 guards before dispatch (gate-enforced)
