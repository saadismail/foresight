# FS-75 · Generated native project or build cache not regenerated after a config, asset or cache change

In Expo projects ios/ and android/ are generated by expo prebuild (often gitignored), and New-Architecture codegen headers live in DerivedData/ios/build. Icon, splash, app.json and config-plugin changes need prebuild --clean on both platforms, incremental xcodebuild reuses an already compiled Assets.car, a DerivedData wipe needs prebuild/pod install before archiving, and helper scripts may not run prebuild at all. Skipping regeneration ships stale assets on one platform or fails the archive on missing ReactCodegen headers.

**Triggers**
- icon, splash, app.json, config-plugin or native dependency changes followed by an incremental build
- DerivedData or ios/build was deleted and the next step is an 'archive-only' shortcut
- a rebrand/asset change verified only on the platform currently open in a simulator
- a runbook says a release script runs prebuild, and nobody has read the script body this session

**Guards**
- After any asset/config/plugin change or cache wipe, run expo prebuild --clean for BOTH ios and android (then pod install) before building; never trust incremental xcodebuild for assets
- Diff each platform's generated asset hash/mtime against the new source and cold-install to check the launch frames
- Read a release helper's actual body before relying on a runbook's description of it, and correct the runbook
