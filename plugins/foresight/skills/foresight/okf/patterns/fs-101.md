# FS-101 · Verification and review gates applied uniformly across a large multi-agent run

A multi-hour, multi-lane run applies the same heavy gate to every task: a whole-app suite (1000-2800 tests, 5-8 min under load) on every dispatch and fix round, Opus review plus re-review per task including minors, and final gates that re-run full suites and multi-viewport galleries already green on the same code. Subagents also issue test commands with new flags and env prefixes outside the pre-approved allowlist. The run spends most of its wall clock on redundant gates or stalls on permission prompts, and the load from redundant runs makes other lanes' tests flaky.

**Triggers**
- a plan with dozens of tasks per lane and a per-task review plus re-review policy
- a dispatch template that mandates a whole-app 'wide run' per task and per fix round
- an exit-gate plan that repeats full-suite runs and screenshot galleries after every merge regardless of what changed
- a long autonomous run whose subagents invoke pytest/vitest/playwright or scripts with varying env prefixes

**Guards**
- Tier gates by scope: scoped test files per task and fix round, the lane's suite once per wave, the full suite once on the final merged tree; re-run only what the change touched
- Batch reviews per wave or by risk class and send minors to a follow-up list instead of fix rounds
- Before launch, allowlist the exact command shapes subagents will run (test runners with their env prefixes and DB names) and put those exact commands in the briefs
