# FS-99 · Document-parsing heuristic tuned on synthetic or single sample documents

Parsers and change detectors for real-world documents (Word BRDs through pandoc, meeting transcripts, minutes) are built against synthetic fixtures or tuned from one real sample: a colon-prefix speaker rule, a TOC line pattern, a heading-level rule, a noise-suppression skip rule. The next document differs (heading style != numbering, TOC kept as content, requirements authored as tables, a body that is all front matter, 'Action items:' headings), and the heuristic misreads or deletes real content. The real-document gate runs last, so the misfit surfaces at the end of the build.

**Triggers**
- a spec names real-document risk for an import/parse feature while all fixtures are synthetic
- changing a parsing heuristic because of one real document
- a skip or strip rule keyed on a loose line pattern or an absence condition (no anchors, colon prefix, TOC-shaped line)

**Guards**
- Get several real documents at plan time (ask the user for customer samples) and run the real-document import gate from the first parser task, not in a final lane
- Keep a corpus of edge-shaped fixtures (style != numbering, TOC, table-authored requirements, doc-control tables, an all-front-matter body, 'Heading:' lines) and run every heuristic change against all of them
- Give every removal or skip heuristic a negative example, confirm matches against structure (TOC entries map to real headings) before deleting content, and guard a generalized fix with the condition of the sample it came from
