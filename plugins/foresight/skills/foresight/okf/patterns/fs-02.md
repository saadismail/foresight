# FS-02 · Verification against an environment not running the code under test

Tests or manual checks run against a server, bundle, dependency set, DB schema or measurement config that predates or differs from the code being verified: daphne/--noreload servers never restarted, Vite from another branch, reuseExistingServer adopting a foreign process, deps not reinstalled after a rebase, symlinked node_modules, unmigrated DB, Silk-enabled dev settings for query counts. The pass/fail reflects the stale environment, not the change.

**Triggers**
- backend code edited, branch switched or migration added while a dev/e2e server started earlier is still running
- Playwright config uses reuseExistingServer or a fixed port another worktree may hold
- just rebased/merged onto a base that may add packages; fresh worktree with symlinked or missing node_modules/venv/build dirs
- measuring query counts or latency via a running dev server or a bench harness with its own settings
- a --keepdb test database kept across a pull that added migrations; a fresh worktree without the non-committed env file
- a live e2e suite run against a backend that is 'already up' on the expected port; a fresh branch/worktree after main merged a Playwright or tooling bump; several worktrees pointing at one local sqlite file
- a server for a worktree launched from another checkout's cwd while worktrees share one venv (cwd at sys.path[0] beats PYTHONPATH)

**Guards**
- Restart BE/FE servers (or confirm the process start time is newer than the last edit) before trusting any red/green result
- Before e2e: confirm the ports are free or owned by this worktree (lsof -iTCP -sTCP:LISTEN), run migrate plus a health check, and reinstall deps (npm ci, pip install -e .) after any base change
- Give each worktree its own real node_modules/venv; never symlink across worktrees
- Measure query counts under settings.test with Silk off, assert the active settings module, and repeat timing runs
- Drop/recreate the --keepdb test DB after pulling migrations, and diff a fresh worktree's env file against a known-good one before trusting a blank screen
- Curl a version/health endpoint (or check the listening process's cwd and git SHA) before running a live suite against an existing server; run migrate after every branch/worktree switch; run a fresh install and `playwright install` whenever the installed versions differ from package.json
- Launch servers from the worktree cwd and assert `python -c 'import pkg; print(pkg.__file__)'` points into it
