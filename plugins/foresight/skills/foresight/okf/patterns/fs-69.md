# FS-69 · Store purchase, offer or redemption flow built on assumed platform semantics

App Store / Google Play / RevenueCat flows are built or explained from memory: the generic play.google.com/redeem page is assumed to accept subscription offer codes, RevenueCat presentCodeRedemptionSheet() wraps a deprecated StoreKit-1 API that resolves without presenting anything, a purchase completed outside the app is never synced (no syncPurchases on foreground), a recreated ASC offer silently defaults to one territory, and sandbox/TestFlight redemptions never reach the production entitlement store. Console navigation is asserted to the user without seeing it. Promise resolution and unit tests pass; only a real account on a real device against the live store exposes it. Store-specific sibling of FS-42.

**Triggers**
- implementing or changing a purchase, offer-code, promo or redeem path on iOS or Android
- calling an SDK method that bridges a native store sheet (presentCodeRedemptionSheet and similar) and checking it only by promise resolution or a log line
- the purchase or redemption now happens outside the app (deep link, browser, App Store / Play page)
- recreating or editing a live App Store Connect subscription offer, price or territory set through the API
- about to tell the user where an option lives in App Store Connect, Play Console or RevenueCat without seeing their screen
- billing sync reports synced:false while users report successful redemptions

**Guards**
- Before building, read the store's current documentation for the exact product type (subscription vs one-time) and code type (custom vs one-time) and cite it; then test end to end with a real account on a real device
- Verify the visible effect on device (sheet shown, entitlement flipped), not promise resolution; check the SDK changelog/issues for wrappers around deprecated OS APIs
- Whenever entitlement can be granted outside the SDK purchase call, call Purchases.syncPurchases()/restore on the next foreground and test the external round trip
- When recreating an ASC offer, diff the new territory list against the old one before deactivating the old offer and abort if it shrinks
- Log the receipt environment (sandbox vs production) on every billing sync call and watch the ratio
- Ask for a screenshot or WebFetch the platform's current docs before giving console navigation steps; flag region- or config-gated options as unverified
