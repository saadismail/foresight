# FS-10 · Interaction verified only on the mouse happy path

Controls work for a mouse click on the main path but fail for keyboard, focus, assistive tech or overlay stacking: unassociated labels, hover-only visibility, div rows without role/tabIndex, nested buttons, portals inside an inert modal, Escape consumed by the parent form, focus dropped by disabling the trigger, SVG labels stealing clicks, and missing empty/error/rejection states.

**Triggers**
- a new clickable row, chip, chart segment, SVG node or hover-reveal control
- a popover/portal rendered inside a modal, or a form-level Escape/outside-click handler
- a button disabled while async work runs, or a shared Modal/Drawer reused (focus trap/restore)
- a list with filters/search, a query that can skip or error, or a validation branch that can reject
- a React Native return-key focus-advance chain (returnKeyType/onSubmitEditing) passes through a custom input component
- a modal with a capture-phase Escape handler hosts a combobox/listbox; a disabled control whose reason is shown only through title
- a nested focusable control (toggle, menu button) inside a clickable card that has its own onKeyDown; a fix removing role/tabIndex/onKeyDown from the only keyboard entry point to an action
- a hand-rolled pointer drag-to-pan/resize wired only to pointerdown/pointerup
- a tap handler awaits a slow device API (GPS fix, network) before flipping any visible loading or disabled state
- an AC whose core action is a click, drag or selection inside rich-text editor content or a pointer-driven overlay (capture region, annotate)
- a list action that removes the focused row and refetches; an aria-label passed to a control that renders its own label

**Guards**
- Tab through new UI in the e2e: every control reachable with a visible focus ring, Enter/Space activate, Escape closes the innermost overlay, focus returns to the trigger
- Use the shared keyboard-accessible row/button pattern and htmlFor/id label pairs; hover-reveal via opacity, never visibility:hidden
- Test empty, filtered-empty, loading, error and rejected states explicitly and give each a message
- Click the real hit target in e2e (near labels, on handles), not only the testid element
- List every field in order and wire each custom input's imperative focus() handle into the chain; press Next through every field on device
- In e2e open the inner popup, press Escape and assert only it closes; put disabled-state reasons in aria-describedby or adjacent visible text
- Nested controls stop propagation in their own key handler, tested with Enter/Space on the nested control asserting the parent handler did not fire; when removing an interactive role, substitute a real Link/button and keep the reachability test
- Custom drag gestures: primary button only, preventDefault/user-select: none on start, reset on pointercancel, lostpointercapture and window blur, with a test for an interrupted drag
- Flip loading/disabled UI synchronously in the press handler before any await, and test it is set in the same tick
- Every pointer interaction in an editor or overlay ships its keyboard route in the same task; the plan's AC table has a keyboard row for each pointer AC
- After a mutation removes the focused row, move focus to an element in the post-refetch list, and don't add aria-label on top of a self-labelling control
