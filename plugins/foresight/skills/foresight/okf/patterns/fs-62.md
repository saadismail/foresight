# FS-62 · Bug class fixed in one template-copied sibling survives in the others

A family of near-identical functions for different entity types (one ledger-posting function per source type such as deposit, expense, merchandise and fuel; a P&L report module beside a balance-sheet report module; backfill scripts beside the pipeline) was built by copying one template. A bug in the template (child-row date/location/organization instead of the parent daily entry's, update_or_create keyed on one FK, a NULL-excluding filter, abs() after aggregate, a status gate for one subtype) is fixed where it was reported, and the other copies keep it until each is rediscovered in a later reconciliation round.

**Triggers**
- fixing a bug in one function whose name follows a family pattern (a shared posting-function prefix, *_view, fix_*)
- the fix changes how a field is sourced (date, location, organization) or how a lookup is keyed
- a gate or rule exists for one subtype (expense checks) of a model with sibling subtypes

**Guards**
- After the fix, grep every sibling in the family (and adjacent backfill/fix scripts) for the same pattern and fix or document each before calling it done
- Diff sibling functions line by line for field sourcing and lookup keys, and enumerate every field copied from the wrong source, not just the one that triggered the bug
- Add one regression test per sibling or subtype, and extract the shared piece into a helper
