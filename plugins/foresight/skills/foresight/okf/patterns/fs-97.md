# FS-97 · Base branch changes behaviour a feature branch relies on, with no textual conflict

While a feature or integration branch is in flight, the base branch changes the behaviour of something it calls: a list/query service is re-scoped (a document list service narrowed to workspace members, so the bot principal sees nothing), a service the branch is rewriting gains new get semantics, a duplicate mechanism or new consumer of a shared component lands, or a module an e2e spec imports is removed. Git merges cleanly because the edits touch different lines, so the break surfaces only when the merged tree is tested, often after the branch was reported green.

**Triggers**
- a feature or integration branch more than a day old whose base received merges touching services, managers, components or modules the branch calls
- the branch rewrites or depends on a shared service (list/get scoping, annotations) or shared component while other tickets land on base
- a principal other than a workspace member (bot, service account) reads through a shared list service
- e2e specs import product modules from src/ instead of API/driver helpers
- base merged into the branch cleanly and no tests were run afterwards
- a stale branch hundreds of commits behind a base that upgraded tool majors (Vitest, lint plugins); two branches that each fixed the same spec's date/clock setup differently

**Guards**
- Merge the base branch into the feature/integration branch every wave (at least daily) and re-run the scoped tests and touched e2e specs on the merged tree before reporting green
- Before merging, grep base's diff since the fork (git diff $(git merge-base HEAD origin/staging) origin/staging) for every service, manager, component and module your branch calls; read each behaviour change and pin the behaviour you rely on with a test
- Pin cross-principal behaviour with one test per principal type (member user, bot, service account) on any shared service the branch reads through
- Keep e2e specs on API/driver helpers, never product modules, and type-check tests/e2e after every merge
- Before merging a stale branch diff package.json/tool majors between merge-base and base; after merging run git log origin/base -- <file> for every file touched on both sides and rerun those specs
