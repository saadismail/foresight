# FS-109 · Waiting state with no deadline when its resolver disappears

A record or process enters a waiting state (pending, updating, held, mismatch) whose only exit is an event from another actor: a watcher, a callback, a renderer or a follow-up flow. When that actor dies, restarts or is never started, nothing moves the state on and it holds forever: a node stops sending heartbeats, a run never settles, a badge says updating indefinitely. Tests always drive the resolver, so the never-resolves path is first exercised live.

**Triggers**
- a new pending, held or verifying state that is cleared only by another process, callback or user action
- a hold that suppresses a liveness signal (heartbeat, lease renewal) until a check passes
- a watcher or supervisor process that may be absent after a restart or an upgrade

**Guards**
- For every waiting state write down the event that ends it and a deadline that moves it to a reported terminal state (failed, rolled back)
- Test the resolver never arriving: kill the watcher or drop the callback, advance the clock past the deadline, and assert the state ends and liveness resumes
