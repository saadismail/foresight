# FS-33 · Test double or harness silently diverges from the real runtime

Mocks, fakes and harness setup are more permissive than, or never intercept, the real dependency: stateful MSW handlers without the backend's scoping and rules, a fake CLI without reserved-name validation, monkeypatching a queryset method the code doesn't call, bespoke render wrappers missing providers, jsdom clipboard/userEvent ordering, caplog on propagate=False loggers, Playwright '*' globs that don't cross '/', destructured request methods, missing xfail markers. Tests go green without exercising reality.

**Triggers**
- writing a stateful mock handler or a fake for a backend/CLI that has business rules
- mocking one method (filter) where the code may call another (select_for_update)
- a custom render wrapper, clipboard mock, caplog assertion or page.route glob
- a docstring claims tests are xfail/expected-fail
- a concurrency test with threads inside django TestCase; near-duplicate Gherkin steps bound to mock vs live implementations
- a fake collaborator returns a fixed correct value where the real one derives it from input; a harness copies the repo with blanket excludes (.git)

**Guards**
- Derive mock rules from the backend service (scope by route params, same allowed transitions), one test per rule
- Assert the mock/route handler was actually hit; use /** globs and call request.method()
- Use the shared renderWithProviders, check logger propagate settings before caplog, and call userEvent.setup() before defining clipboard mocks
- Revert the fix and confirm the test fails
- Make fakes reproduce the real input-dependent behavior; grep the suite for reliance on excluded dirs (git rev-parse) and compare harness pass counts with a full checkout
