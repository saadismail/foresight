# FS-83 · Shared CSS class, combinator or container rule reused beyond the shape it was written for

Plain CSS in a shared stylesheet or design-system package is reused by name: a generic class (a wizard container class, a page header, a rejection-reason callout) goes onto a structurally or semantically different component, an app override targets a selector the DS package already styles, and a `.field + .field` rhythm rule or flex-column stretch default written for stacked children also fires on grid columns or inline buttons. Cascade order and specificity pick a winner silently, so a fix looks applied in one layout and fails in another, and each fix covers only the sibling shape that was reproduced first.

**Triggers**
- a new component's root className matches a class already styled elsewhere in the same stylesheet or in a DS package
- an app-level stylesheet overrides a selector also defined by a consumed shared/DS package
- reusing a class named for another meaning (reason, error, danger) as a generic callout box
- an adjacent-sibling (`.a + .b`) or descendant spacing rule in a stylesheet that also renders multi-column grid rows
- a shared header/card class ported from a simpler portal into one that adds children (actions, buttons); a button placed directly inside a flex-column container

**Guards**
- Grep the class name across every stylesheet (app and DS package) before reusing or overriding it; give a new layout a modifier or component-specific class instead of relying on source order
- When a CSS change doesn't apply, inspect computed styles for the winning rule and its source file before changing the selector; scope overrides by ANDing a component class onto the shared one
- Scope rhythm rules to a stack container class; when fixing a `+`-combinator bug, enumerate every sibling shape that can follow the anchor and assert each one (top-edge delta for multi-column rows)
- Set align-self or width explicitly for controls inside flex-column rows, and add position/size assertions (not only presence) for ported headers and action rows
